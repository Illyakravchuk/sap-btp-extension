## Короткий опис програми

Даний програмний продукт є спеціалізованим бекенд-застосунком на базі Node.js, розробленим для автоматизованого моніторингу, аналітики ресурсів та управління горизонтальним масштабуванням контейнеризованих сервісів. 

**Ключові архітектурні особливості:**
* **Dual Mode Security:** Автоматична адаптація середовища. У хмарі SAP BTP використовується криптографічна автентифікація через SAP XSUAA (JWT-токени). На локальному сервері система автоматично переходить у локальний режим без втрати функціональності Role-Based Access Control (RBAC).
* **Аналітика та прогнозування:** Інтегрований модуль машинного навчання, що використовує алгоритм лінійної регресії для аналізу часових рядів. Модель аналізує «ковзне вікно» історичних даних навантаження на CPU та динамічно прогнозує виснаження ресурсів кластера (статуси `NORMAL`, `WARNING`, `CRITICAL`).
* **Оркестрація:** API для зміни кількості активних інстансів (горизонтальне масштабування) з розподілом навантаження.
* **Стрес-тестування:** Наявний вбудований генератор фонового навантаження для тестування реакції системи в реальному часі.

## Супровідне ПЗ (Вимоги до середовища)

Для успішного розгортання та запуску необхідне наступне ПЗ:
* **Операційна система:** Linux (Ubuntu 20.04 / 22.04 LTS або новіша) або Windows 10/11.
* **Середовище виконання:** Node.js (LTS версія 18.x або новіша).
* **Менеджер пакетів:** npm (постачається разом із Node.js).
* **Контейнеризація (опціонально):** Docker Engine та Docker Compose (для ізольованого запуску без встановлення оточення на хост).
* **База даних:** 
  * *Локальний режим:* Окреме встановлення СУБД **не потрібне** – сервер працює автономно в оперативній пам'яті (In-Memory state).
  * *Хмарний режим (SAP BTP):* Сервіс PostgreSQL on SAP BTP (Hyperscaler Option), прив'язка до якого здійснюється автоматично через сервісні біндинги `VCAP_SERVICES`.
* **Основні бібліотеки (залежності):** `express`,  `@sap/xsenv`, `@sap/xssec`, `pg` (встановлюються автоматично командою `npm install` згідно з `package.json`).

## Порядок встановлення 

### Варіант 1. Контейнеризований запуск

### 1. Клонувати репозиторій та перейти в робочу директорію:

```bash
git clone https://github.com/Illyakravchuk/sap-btp-extension.git
cd sap-btp-extension
```

### 2. Запустити застосунок однією командою

```bash
docker compose up -d --build
```

### 3. Перевірити роботу системи

Відкрийте браузер за адресою:

```text
http://localhost:8080
```

або:

```text
http://<IP_сервера>:8080
```


### 4. Зупинка сервісу

```bash
docker compose down
```

### Варіант 2. Прямий запуск на хості

Для запуску безпосередньо в середовищі операційної системи:

### 1. Клонувати репозиторій та перейти в робочу директорію

```bash
git clone https://github.com/Illyakravchuk/sap-btp-extension.git
cd sap-btp-extension
```

### 2. Встановити залежності

```bash
npm install
```

### 3. Створити конфігураційний файл `.env`

Створіть файл `.env` у кореневій папці проєкту (значення паролів наведені як приклад і можуть бути змінені):

```env
ADMIN_PASSWORD=SecretAdmin1!
OPERATOR_PASSWORD=OperatorPass!
```

### 4. Запустити сервер застосунку

```bash
npm start
```

У терміналі з'явиться підтвердження:

```text
Локальний режим: SAP-сервіси недоступні.
SAP BTP Advanced Manager API is running on port 8080
```

### 5. Запустити інтеграційні тести

Для комплексної перевірки працездатності потрібно відкрити окремий термінал і виконати:

```bash
node test.js
```

## Інструкція користувача

### 1. Авторизація в системі

1. Перейдіть у веб-браузері за адресою `http://localhost:8080` (або IP-адресою сервера).
2. Оберіть облікову роль:

   * **Admin** – повний доступ: моніторинг, горизонтальне масштабування та генерація навантаження. Пароль: встановлений у файлі `.env` (за замовчуванням: `SecretAdmin1!`).
   * **Operator** – режим аудиту: виключно читання метрик без права зміни конфігурації. Пароль: встановлений у файлі `.env` (за замовчуванням: `OperatorPass!`).
3. Натисніть кнопку входу. Система згенерує відповідний сесійний токен і відкриє дашборд.

### 2. Моніторинг та аналітика

* **Панель метрик** – відображає поточний стан застосунку, використання пам'яті кластера (RAM) та поточне навантаження на CPU.
* **Предиктивна модель (CPU):** відображає поточне завантаження процесора та прогнозне значення, розраховане алгоритмом машинного навчання (на основі лінійного тренду останніх вимірів). Система автоматично визначає поточний стан (статуси `NORMAL`, `WARNING`, `CRITICAL`) і надає текстові рекомендації щодо необхідності автомасштабування інфраструктури.

### 3. Управління масштабуванням (тільки для Admin)

* У блоці **«Оркестрація Cloud Foundry»** відображається поточна кількість запущених екземплярів мікросервісу, завантаження процесора та виділена квота пам'яті.
* Для виконання горизонтального масштабування використовуються кнопки керування:
  * Кнопка **`+`** – створює новий паралельний екземпляр застосунку (Scale-Out) для розподілу обчислювального навантаження.
  * Кнопка **`-`** – зменшує кількість активних копій (Scale-In) при зниженні активності.
* При натисканні система надсилає запит на бекенд, перераховує стан кластера та адаптує розподіл навантаження.

### 4. Генерація навантаження (Контроль навантаження CPU)

1. У блоці **«Аналітика та Інтеграції»** оберіть вкладку **«Прогноз ресурсів»**.
2. У секції **«Інструменти тестування»** знайдіть блок **«КОНТРОЛЬ НАВАНТАЖЕННЯ CPU»**:
   * Натискайте кнопку **`+`**, щоб збільшити інтенсивність обчислень (відобразиться поточний рівень, наприклад `Рівень: 2`).
   * Кнопка **`-`** дозволяє поступово зменшити інтенсивність.
3. Спостерігайте у блоці **«Предиктивна модель (CPU)»** за зміною поточного завантаження та перерахунком прогнозу (перехід між статусами `NORMAL`, `WARNING`, `CRITICAL`).
4. Після завершення тесту натисніть червону кнопку **`Stop`**, щоб повністю скинути навантаження та звільнити процесор.
